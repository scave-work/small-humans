Comment ce site a été fait

25 octobre 2026

Ce site, je ne l'ai pas codé seul : je l'ai construit en discutant avec Claude, une IA qui écrit et modifie du code dans mon dossier de travail. Voici comment on s'y prend quand on débute avec ce genre d'outil, et ce que j'ai appris en route.

Deux dépôts : un privé, un public

Le site vit dans un dépôt GitHub public, publié gratuitement par GitHub Pages. À côté, un dépôt privé, « l'atelier », garde ce qui n'a rien à faire en ligne : consignes, brouillons, décisions, dessins originaux. Règle de base : rien de secret dans le public, jamais.

Un fichier de consignes et un journal de décisions

Claude oublie tout d'une conversation à l'autre. Alors j'ai deux fichiers qu'il relit au départ : un CLAUDE.md (les règles du projet : répondre en français, donner les commandes prêtes à coller, ne rien supprimer sans demander) et un journal où chaque décision que je prends est notée tout de suite. Quand je change d'avis, je le dis, et ça s'écrit.

Beaucoup de prompts, des passations

Un seul gros prompt ne suffit pas. J'ai procédé par petites demandes, une étape à la fois, avec des maquettes à valider avant de généraliser un style. Quand une conversation devient trop longue, Claude s'embrouille : on écrit alors une « passation » (où on en est, quelles règles, quels pièges) et on repart d'une session neuve avec un prompt de reprise.

Des skills

Un skill est un mode d'emploi réutilisable qu'on donne à Claude pour un type de tâche. J'en ai utilisé un pour la direction visuelle (éviter le look « fait par une IA »), et d'autres sont prévus pour ajouter un film, gérer la musique ou publier avec un contrôle des secrets.

Des robots pour les tâches répétitives

Pour le cinéma, des petits robots GitHub (les « Actions ») tournent tout seuls : ils mettent à jour le catalogue de nouveautés, la base des titres et intègrent les films que j'ajoute depuis mon téléphone. Le site reste utilisable sans Claude : les données sont de simples fichiers JSON lisibles.

Ce que je retiens

  • Écrire les décisions, sinon elles se perdent.
  • Avancer par petites étapes et valider à l'œil avant de continuer.
  • Garder le privé et le public bien séparés.
  • Tester sur le téléphone, c'est là que le journal de films sert vraiment.
