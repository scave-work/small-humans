3. Règles de travail (CLAUDE.md)

# CLAUDE.md : squelette utilisé
- Projet perso, séparé du travail. Répondre en français, simplement.
- Niveau de l'utilisateur : commandes prêtes à coller, une phrase pour tout ce qui touche à l'IA.
- Deux dépôts : privé (consignes, brouillons) / public (le site : jamais de secret).
Règles de travail
1. Décision de l'utilisateur = notée tout de suite dans 00_CONTEXTE.md, puis commit du seul fichier.
2. Tout ce qui est publié est public : contrôle des secrets avant chaque push ; « ok » demandé pour tout contenu sensible.
3. Git : add fichier par fichier, messages en français (quoi + pourquoi), pas de --force, pas de suppression sans accord.
4. Aucun secret dans aucun dépôt (jetons, mots de passe, clés).
5. Le site doit rester utilisable sans Claude : données en JSON/Markdown lisibles.
6. Tout travail non trivial : écrire la méthode et les commandes pour le refaire ailleurs.
7. L'utilisateur valide l'esthétique : maquette ou capture avant de généraliser.
8. Dessins originaux : références en lecture seule.

4. Cycle de session

  • 1 session = 1 chantier (musique, cinéma, design).
  • Garde-fou : un hook (script lancé automatiquement par Claude Code) surveille la taille du contexte. À 250 000 tokens, il demande à Claude d'ouvrir une nouvelle session, une seule fois par session.
  • Passation = fichier « état, règles, pièges » + prompt de reprise à coller. Présents : prompts/ (6 prompts) et docs/.
  • Git : git add <fichier> → git commit -m "…" -- <fichier> → git pull --rebase → git push. Jamais --force.
ÉlémentDétail
DéclencheursUserPromptSubmit (message envoyé) et PostToolUse (après chaque outil)
Mesureentrée + cache créé + cache lu de la dernière réponse, lus dans la fin du transcript
Actioninjecte une consigne : mettre à jour la passation/le prompt de reprise, puis ouvrir une session avec un brief complet
Limiteun hook ne peut pas ouvrir la session lui-même ; un drapeau évite de répéter la consigne
Configurationréglages utilisateur de Claude Code (~/.claude/settings.json), hors dépôts

Prompt complet (à copier)
Tu travailles sur mon site personnel « Small Humans » (dépôt privé). Réponds en français, simplement, une étape à la fois. Ne commite rien sans mon accord explicite. Aucun secret dans aucun fichier.

MÉTHODE DE TRAVAIL (effort maximal)
Travaille à fond, sans raccourci : lis tout avant d'agir, vérifie chaque affirmation, reprends ton travail tant qu'il n'est pas à la hauteur. Distingue ce que tu as vu, ce que tu supposes et ce que tu conclus. Ne prétends jamais avoir vérifié ce que tu n'as pas ouvert ou mesuré.

UTILISATION DE TASTE
Utilise la skill design-taste-frontend (/design-taste-frontend) pour l'intégralité du travail HTML :
- lis son SKILL.md en entier avant de commencer ;
- lance son tirage de directions (scripts/draw.mjs) ; choisis la direction la plus proche de « station spatiale vue de dessus, inspirée d'Ixion » et justifie ton choix ; si aucune ne convient, dis-le au lieu d'en forcer une ;
- vérifie avec son inspecteur (scripts/inspect.mjs) aux 3 largeurs, puis boucle « regarder les captures, corriger, regarder à nouveau » ;
- PRIORITÉ : en cas de conflit, mes consignes ci-dessous passent avant celles de Taste. Exemple : Taste déconseille les halos, mais j'en autorise un (voir 07).

01 COMMUNICATION
Avant de commencer, pose-moi des questions sur ce que je veux : le message, le mot principal, la couleur d'accent, le son. Si je saute un point, propose une valeur et dis-la.
Valeurs par défaut : message « Quatre passions, une station » ; mot principal « SMALL HUMANS » ; accent bleu glacé #6FA8FF.

02 RÉFÉRENCES
- Image clé Ixion que je fournis : station annulaire vue de dessus, anneaux concentriques, cellules lumineuses blanc-bleu en cercle, coque gris-bleuté éclairée de côté, titre blanc en capitales très espacées sur fond d'espace presque noir. Analyse-la avant de commencer (palette, matières, lumière, composition).
- Dans le dépôt : design/ideee/KIT_STYLE_REEL1.md (grammaire de mouvement), design/ideee/maquette-v6-station.html (première interprétation), design/ideee/maquette-v5-reel1.html (intro, galerie, page Musique).
- INTERPRÉTATION ORIGINALE : ne copie aucun élément du jeu (logo, images, musique).

03 FORMAT
Page HTML/CSS/JS autonome (aucune dépendance externe obligatoire), utilisable sans Claude. Intro animée de 15 secondes (touche l'écran pour passer), puis galerie de 4 « tableaux » (musique, cinéma/séries/anime, écriture, tech/IA), puis la page Musique. Référence mobile 1080x1920 (9:16) et ordinateur 1920x1080 ; fluidité visée : 60 images par seconde. Données (titres, tags) dans un fichier JSON lisible, pas dans le code.

04 RÈGLES
- Le fond sombre occupe au moins 60 % de l'écran.
- Une seule police, une seule couleur d'accent (#6FA8FF).
- Texte principal d'au moins 64 px à l'écran d'intro, un seul texte principal à la fois, titre lisible au moins 1 seconde.
- Sur mobile, rien d'important dans les 250 px du bas.
- Respecte prefers-reduced-motion (version sans animation).

05 ESTHÉTIQUE
- Palette : fond #05080F, bleu nuit #111F38, coque #55596C, acier clair #BABBCF, texte #F2F5FF, accent #6FA8FF.
- Typo : sans-serif géométrique large, capitales, interlettrage d'au moins 0,25 em (type Raleway, à valider avec moi).
- Texture : grain fin, étoiles fines, coque métallique.
- Lumière : rasante, froide, d'un seul côté ; les cellules lumineuses blanc-bleu sont les seules sources vives ; ombres profondes.

06 MOUVEMENT
- Texte : lettres qui apparaissent une par une (décodage de 3 caractères maximum), rebonds courts (moins de 150 ms) uniquement sur le texte.
- Anneau qui tourne très lentement, cellules qui s'allument une par une, poussée de caméra lente (zoom 1,0 vers 1,15).
- Aucun temps mort de plus de 0,5 s sans mouvement.

07 INTERDITS
Fondus enchaînés, emojis, rose / magenta / violet / orange vif, bonhommes bâtons, particules décoratives, dégradés colorés, texte qui clignote. Halo autorisé uniquement sur les cellules lumineuses et le titre, à un seul niveau d'intensité.

08 RYTHME + SON
72 BPM (un temps = 0,83 s). Il se passe quelque chose à chaque temps. Son optionnel et désactivé par défaut (bouton) : clic de console discret par cellule allumée, sub-basse au titre, sons synthétisés (Web Audio) ou libres de droits, jamais un extrait de la bande-son du jeu.

09 SCÈNE
[0 à 4 s] : noir, les étoiles apparaissent, l'anneau se dessine (cercles concentriques vus de dessus), une cellule s'allume à chaque temps.
[4 à 8 s] : le titre « SMALL HUMANS » se forme lettre par lettre au centre de l'anneau ; sous-titre « MUSIQUE · CINÉMA · ÉCRITURE · TECH & IA ».
[8 à 15 s] : poussée de caméra ; les 4 quarts de l'anneau s'allument, chacun avec le nom d'une passion ; les 2 dernières secondes, titre seul tenu, puis passage à la galerie.

10 VALIDATION
Avant de me présenter le résultat, analyse ton propre travail : montre-moi le découpage temps par temps, 4 captures de l'intro (à 2, 6, 10 et 14 s) et les captures de la galerie et de la page Musique aux 3 largeurs ; vérifie que chaque texte est lisible et juste (accents compris), le contraste, les zones interdites et le rapport de Taste (inspecteur). Corrige ce qui ne va pas, puis seulement présente le résultat avec ses limites connues.

Version à variables ({{SITE}}, {{MOT}}, {{ACCENT}}, {{DUREE}}, {{BPM}}…) : design/PROMPT_MODELE_INTRO_TASTE.md dans l'atelier.

10. Refaire un site équivalent : checklist

  1. Créer 2 dépôts (privé / public) ; écrire CLAUDE.md et 00_CONTEXTE.md avant tout code.
  2. Données d'abord (JSON/CSV lisibles), design ensuite ; maquette validée avant de généraliser.
  3. Un prompt par chantier, structuré en blocs, avec valeurs chiffrées et interdits.
  4. Scripts reproductibles (entrée → sortie documentées, retour arrière noté).
  5. Automatiser le répétitif par GitHub Actions ; clés en secrets, jamais dans le code.
  6. Tester sur téléphone ; publier après contrôle des secrets ; noter chaque décision.
